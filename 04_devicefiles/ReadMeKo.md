# 04_devicefiles

디바이스 파일, 디바이스 번호, 블록/문자 디바이스에 대한 소개입니다.

## 디바이스 파일(Device files)

디바이스 파일은 유저 스페이스(userspace)와 Linux 드라이버/커널 모듈 사이의 인터페이스로 사용할 수 있습니다. 일반적으로 디바이스 파일은 `/dev` 폴더 아래에 있지만, 어디에든 생성할 수 있습니다. 또한 대부분의 디바이스 파일은 임시 파일이며, Raspberry Pi의 전원을 끄고 SD카드를 PC에 꽂아 `dev` 폴더로 들어가 보면 거의 비어 있는 것을 볼 수 있습니다.

일반 파일을 `ls`로 보면 다음과 같이 보입니다.

~~~
-rw-r--r-- 1 pi pi 1169 Dec  6 20:08 README.md
~~~

앞의 `-`는 일반 파일임을 의미합니다. 그 다음은 파일 권한, `1`은 파일을 가리키는 하드 링크의 수입니다. 이어서 소유자/그룹, 바이트 단위 파일 크기, 마지막 수정 날짜와 파일명이 표시됩니다.

디바이스 파일을 보면 `ls` 출력이 약간 다릅니다.

~~~
crw-rw---- 1 root gpio    254,  0 Dec  7 14:07 /dev/gpiochip0
brw-rw---- 1 root disk    179,  0 Dec  7 14:07 /dev/mmcblk0
brw-rw---- 1 root disk    179,  1 Dec  7 14:07 /dev/mmcblk0p1
crw-rw---- 1 root dialout   4, 64 Dec  7 14:07 /dev/ttyS0
~~~

겉보기는 비슷하지만 두 가지 차이가 있습니다. 첫 번째는 맨 앞 글자입니다.

## 문자 디바이스와 블록 디바이스(Character and block devices)

일반 파일은 맨 앞이 `-`인데, 여기서는 `c`와 `b`가 보입니다.

- `c`: 문자(Character) 디바이스
- `b`: 블록(Block) 디바이스

문자/블록 구분은 장치가 데이터를 어떻게 다루는지를 나타냅니다.

예를 들어 `mmcblk0`는 Raspberry Pi의 SD카드에 접근하는 디바이스 파일입니다. SD카드는 블록 단위(예: 512바이트)로 데이터를 전송하므로 블록 디바이스가 됩니다.

`ttyS0`는 Raspberry Pi의 시리얼 포트 디바이스 파일입니다. 시리얼 포트는 바이트(문자) 단위로 데이터를 전송하므로 문자 디바이스가 됩니다.

## 디바이스 번호(Device Numbers)

디바이스 파일의 또 다른 차이는, `ls`가 파일 크기 대신 두 개의 숫자를 보여준다는 점입니다. 예를 들어 `/dev/gpiochip0`의 `254, 0` 같은 값이 바로 디바이스 번호(Device Number)이며,

- Major(메이저) 디바이스 번호
- Minor(마이너) 디바이스 번호

로 나뉩니다. `/dev/gpiochip0`의 경우 Major는 254, Minor는 0입니다.

드라이버와 디바이스 파일의 연결은 **오직 디바이스 번호**로만 이루어집니다. 시스템에서 어떤 디바이스 번호가 사용 중인지 보려면 `/proc/devices`를 확인하세요. 위에서 본 번호를 찾아보면 다음과 같이 나옵니다.

~~~ 
grep 179 /proc/devices 
179 mmc
grep 4 /proc/devices 
  4 /dev/vc/0
  4 tty
  4 ttyS
grep 254 /proc/devices 
254 gpiochip
~~~ 

여기에는 보통 major 번호만 표시됩니다. 일반적으로 드라이버는 major 번호 하나를 할당하고, 그 아래 여러 minor 번호 범위를 관리합니다. minor 번호는 0~255 범위를 가질 수 있습니다. `ls` 출력에서 SD카드의 `mmcblk0`와 첫 번째 파티션 `mmcblk0p1`이 같은 major(179)를 쓰고 minor만 다른 것을 볼 수 있습니다.

하나의 드라이버가 여러 장치를 지원할 때, 같은 major 번호를 공유하는 경우도 흔합니다.

## 디바이스 파일 생성(Creating Device Files)

디바이스 파일과 드라이버의 연결이 실제로 디바이스 번호로 이루어진다는 것을 확인하기 위해 간단한 실험을 해보겠습니다.

먼저 `hexdump`로 SD카드에 기록된 바이트를 볼 수 있습니다.

~~~
sudo hexdump /dev/mmcblk0 | head
0000000 b8fa 1000 d08e 00bc b8b0 0000 d88e c08e
0000010 befb 7c00 00bf b906 0200 a4f3 21ea 0006
0000020 be00 07be 0438 0b75 c683 8110 fefe 7507
0000030 ebf3 b416 b002 bb01 7c00 80b2 748a 8b01
0000040 024c 13cd 00ea 007c eb00 00fe 0000 0000
0000050 0000 0000 0000 0000 0000 0000 0000 0000
*
00001b0 0000 0000 0000 0000 0e14 cf49 0000 0000
00001c0 4001 030c ffe0 2000 0000 0000 0010 0300
00001d0 ffe0 7f83 ffff 2000 0010 1000 01cc 000
~~~

이제 홈 폴더로 이동해 같은 디바이스 번호를 가진 새 디바이스 파일을 만들면, SD카드 내용을 그대로 읽을 수 있어야 합니다. 디바이스 파일 생성에는 `mknod`를 사용합니다.

~~~
cd
sudo mknod mymmc b 179 0
~~~

`mknod`의 첫 인자는 파일명이고, 그 다음은 타입(`b`는 블록 디바이스), 마지막으로 major/minor 번호입니다. 이제 이 파일을 hexdump 해보면,

~~~
sudo hexdump mymmc | head
0000000 b8fa 1000 d08e 00bc b8b0 0000 d88e c08e
0000010 befb 7c00 00bf b906 0200 a4f3 21ea 0006
0000020 be00 07be 0438 0b75 c683 8110 fefe 7507
0000030 ebf3 b416 b002 bb01 7c00 80b2 748a 8b01
0000040 024c 13cd 00ea 007c eb00 00fe 0000 0000
0000050 0000 0000 0000 0000 0000 0000 0000 0000
*
00001b0 0000 0000 0000 0000 0e14 cf49 0000 0000
00001c0 4001 030c ffe0 2000 0000 0000 0010 0300
00001d0 ffe0 7f83 ffff 2000 0010 1000 01cc 000
~~~

출력이 동일한 것을 확인할 수 있습니다.

이번에는 문자 디바이스로도 같은 실험을 해보겠습니다. Raspberry Pi에서 TX와 RX 핀을 점퍼로 쇼트시키고, `raspi-config`에서 시리얼 포트를 활성화하고 시리얼 로그인 콘솔을 비활성화하면, `screen` 같은 시리얼 터미널로 시리얼 포트에 접근할 수 있습니다.

![Shorting the serial port](serial_short.png)

~~~
screen /dev/ttyS0 9600
~~~

입력하는 모든 문자가 그대로 에코(echo)됩니다. 이제 같은 디바이스 번호로 문자 디바이스 파일을 만들어 보겠습니다.

~~~
cd
sudo mknod myserial c 4 64
~~~

이제 이 파일을 `screen`으로 열고 입력하면 똑같이 에코됩니다.

~~~
sudo screen myserial 9600
~~~

여기서 핵심은, 디바이스 파일과 드라이버의 연결이 디바이스 파일의 **이름**이 아니라 **디바이스 번호**로만 이루어진다는 점입니다.
