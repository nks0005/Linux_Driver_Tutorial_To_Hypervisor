# 01_hello

간단한 Hello World Linux 커널 모듈 예제입니다.

이 예제는 Raspberry Pi뿐 아니라 일반 x86 컴퓨터에서도 컴파일하고 실행할 수 있습니다.

## Hello World 커널 모듈

커널 모듈에서 중요한 이벤트는 두 가지입니다.

- 모듈이 커널에 **로드될 때**
- 모듈이 커널에서 **언로드(제거)될 때**

`module_init`과 `module_exit` 매크로를 사용해, 위 이벤트에서 실행될 함수를 지정할 수 있습니다.

모듈이 커널에 로드될 때 호출되는 함수의 프로토타입은 다음과 같습니다.

~~~
int my_init(void)
~~~

이 함수는 `int` 타입의 반환값을 가집니다. 모듈이 정상적으로 로드되면 `0`을 반환하고, 초기화 중 오류가 발생하면 음수의 에러 코드를 반환합니다.

init 함수는 전달받는 인자가 없습니다.

모듈이 커널에서 제거될 때 호출되는 함수의 프로토타입은 다음과 같습니다.

~~~
void my_exit(void)
~~~

이 함수 역시 반환값이나 인자가 없습니다. 목적은 init 함수에서 수행한 작업을 정리(clean up)하는 것입니다(예: 메모리/인터럽트 등 리소스 해제).

두 함수 모두에서 `printk`를 사용합니다. `printk`는 표준 출력으로 출력하는 `printf`와 비슷해 보이지만, 커널 모듈에는 표준 출력이 없습니다. 대신 커널 로그만이 사용 가능한 출력 수단이며, `printk`는 커널 로그에 메시지를 기록합니다.

모듈을 완성하려면 한 가지 중요한 메타데이터가 더 필요합니다. 바로 모듈의 라이선스이며, 다음 매크로로 지정합니다.

~~~
MODULE_LICENSE("GPL");
~~~

여기서는 GPL 라이선스를 사용합니다. GPL은 카피레프트 기반의 자유/오픈소스 라이선스입니다. 또한 커널 모듈에는 라이선스 지정이 필요합니다. 일부 GNU/Linux 배포판은 오픈소스 드라이버만 로드를 허용하기도 합니다. 만약 라이선스를 `proprietary`로 지정한다면, 배포판에 따라 드라이버 로드를 거부할 수 있습니다.

## 모듈 빌드를 위한 Makefile

Linux 커널은 Makefile 기반으로 빌드됩니다. 커널 모듈을 빌드하려면 우리도 Makefile을 작성해야 합니다.

먼저, 커널 모듈로 빌드할 오브젝트 파일을 목록에 추가합니다.

~~~
obj-m += hello.o
~~~

`hello.c`를 `hello.o`로 컴파일하는 작업은 커널 헤더의 Makefile이 자동으로 수행합니다.

다음으로 `all`과 `clean` 두 타깃을 선언합니다. 두 타깃 모두 `/lib/modules/$(uname -r)/build`에 있는 커널 헤더의 Makefile을 호출합니다. `M` 변수를 현재 경로로 설정하면, 커널 헤더 Makefile이 현재 경로에서 빌드할 모듈을 찾게 됩니다.

두 타깃의 차이는 커널 헤더 Makefile에서 어떤 타깃을 부르느냐입니다.

- `all`은 `modules` 타깃을 호출해 모듈을 빌드합니다.
- `clean`은 `clean` 타깃을 호출해 컴파일 중 생성된 파일들을 삭제합니다.

## 모듈 관리 명령어

- 커널 로그를 새 줄이 추가될 때마다 계속 보기:
  ~~~
  sudo dmesg -W
  ~~~
- 모듈 삽입:
  ~~~
  sudo insmod hello.ko
  ~~~
- 모듈 제거:
  ~~~
  sudo rmmod hello.ko
  ~~~
