# 13_ioctl

`ioctl` 소개 이후, 이번에는 Linux 드라이버에서 `ioctl`을 **제대로** 사용하는 방법을 다룹니다.

## ioctl 번호를 더 유니크하게 만들기(Randomising ioctl numbers)

이전에는 `ioctl` 명령으로 단순한 정수 값을 사용했습니다. 하지만 각 디바이스마다 명령이 더 유니크하도록 만드는 것이 바람직합니다. 그래야 다른 디바이스의 명령을 잘못된 드라이버에 보내는 일을 줄일 수 있습니다.

명령은 커널 드라이버와 유저 스페이스 애플리케이션에서 모두 include 할 수 있는 헤더 파일에 정의하는 것이 일반적입니다.

명령 정의 예시는 다음과 같습니다.

- `#define RD_VAL _IOR('a', 'c', int *)`: `_IOR` 매크로는 `RD_VAL` 명령을 위한 번호를 생성합니다. `R`은 커널 스페이스에서 유저 스페이스로 **읽어오는(read)** 명령임을 의미합니다. 첫 두 값은 명령을 식별하기 위한 임의의 바이트(랜덤 값)이고, 마지막 인자는 가독성을 위해 이 명령이 어떤 타입의 인자를 받는지 한눈에 보여줍니다(여기서는 `int *`).
- `#define WR_VAL _IOW('a', 'b', int *)`: `_IOW` 매크로는 `WR_VAL` 명령을 위한 번호를 생성합니다. `W`는 유저 스페이스에서 커널 스페이스로 **쓰는(write)** 명령임을 의미합니다.

## 드라이버에서의 ioctl(ioctl in the driver)

`ioctl` 콜백 함수에서는 보통 지원하는 명령에 대해 `switch case`로 분기합니다. 지원하지 않는 명령은 `default`에서 `-EOPNOTSUPP`를 반환해 “지원하지 않는 명령”임을 알립니다. 그리고 각 명령에 대한 처리를 추가합니다.

커널/유저 스페이스 간 데이터 이동은 08_read_write 예제에서 본 것처럼 `copy_to_user`, `copy_from_user`를 사용합니다.

이 예제에서 지원하는 세 가지 명령은 다음과 같습니다.

- `RD_VAL`: 커널 모듈의 전역 변수 `int answer` 값을 읽어 유저 스페이스로 반환
- `WR_VAL`: 커널 모듈의 전역 변수 `int answer`에 값을 기록
- `GREET`: `s.repeat` 횟수만큼 `s.name`에게 인사 메시지를 출력

## 유저 스페이스 앱에서의 ioctl(ioctl in the user space app)

유저 스페이스 애플리케이션에서는 프로그램에 전달된 인자 개수에 따라 서로 다른 명령을 호출합니다.

- 인자 없음: `RD_VAL`로 answer 읽기
- 인자 1개: `RD_VAL`로 answer 쓰기(예제 설명 그대로 유지)
- 인자 2개: `GREET` 호출
- 인자 2개 초과: 잘못된 `ioctl`을 호출

## 테스트(Testing the code)

`insmod`로 커널 모듈을 로드한 뒤, 유저 스페이스 프로그램을 서로 다른 인자 개수로 실행해 보세요. ioctl 함수가 호출되었다는 메시지가 커널 로그에 출력될 것입니다.
