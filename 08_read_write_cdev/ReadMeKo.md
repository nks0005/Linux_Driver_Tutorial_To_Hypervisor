# 08_read_write_cdev

문자 디바이스(Character Device)에서 읽기(read)와 쓰기(write)를 구현하는 방법을 보여주는 예제입니다.

이 예제는 Raspberry Pi뿐 아니라 일반 x86 컴퓨터에서도 컴파일하고 실행할 수 있습니다.

## 코드 설명(Explaining the code)

이 커널 모듈은 **64바이트 텍스트 배열**을 제공하며, 유저 스페이스에서 디바이스 파일을 통해 이 배열에 쓰거나 읽을 수 있습니다.

테스트 배열은 `static` 전역 변수로 선언되어 있습니다. `static`을 선택한 이유는 모듈 내부에서만 접근 가능하도록 제한하기 위함입니다.

read 함수의 인자들을 살펴보면 다음과 같습니다.

- `struct file *filp`: 리눅스 커널에서 열린 파일을 나타내는 `struct file`에 대한 포인터
- `char __user *user_buf`: 읽은 데이터를 저장할 유저 스페이스 버퍼의 포인터  
  `__user`는 가독성을 위한 매크로로, 유저 스페이스 버퍼를 가리킨다는 점을 강조합니다.
- `size_t len`: 유저 스페이스 버퍼의 길이(바이트)
- `loff_t *off`: 현재 파일 오프셋에 대한 포인터  
  이 예제에서는 `text` 배열에서 현재 읽기/쓰기 위치를 의미합니다.

read 함수는 성공적으로 읽은 바이트 수를 반환합니다.

먼저 실제로 읽을 수 있는 바이트 수를 계산합니다. `text`는 64바이트이므로, 최대 64바이트까지만 읽을 수 있습니다. 읽을 수 있는 양은 현재 파일 위치와 유저 버퍼 길이에 따라 달라집니다.

그 다음 `copy_to_user`로 `text`의 현재 위치에서 `user_buf`로 데이터를 복사합니다. 이 함수는 **복사하지 못한 바이트 수**를 반환합니다.

그리고 성공적으로 읽은 바이트 수만큼 파일 위치를 증가시키고, 그 값을 반환합니다.

write 콜백도 비슷하지만 차이점은 다음과 같습니다.

- `const char __user *user_buf`: 유저 스페이스의 데이터는 커널로 복사될 뿐이므로 `const`
- 유저 스페이스 → 커널 스페이스 복사는 `copy_from_user` 사용

마지막으로 `fops` 구조체에 우리의 콜백 함수들을 등록하면 됩니다.

## 코드 테스트(Testing the code)

모듈을 로드하면 커널 로그에 다음과 같은 출력이 보일 것입니다.

~~~
[ 3038.299101] hello_cdev - Major Device Number: 236
~~~

이제 해당 디바이스 번호로 디바이스 파일을 생성합니다.

~~~
sudo mknod /dev/hello0 c 236 0
~~~

디바이스 파일에 쓰고, 다시 읽어 보면서 드라이버를 테스트할 수 있습니다.

~~~
echo "Hello World!" | sudo tee /dev/hello0
~~~

`tee`를 사용하는 이유는 `/dev/hello0`에 루트 권한으로 쓰기 위해서입니다. 만약 아래처럼 실행하면

~~~
echo "Hello World!" > /dev/hello0
~~~

`echo`만 루트로 실행되는 것이 아니라(또는 반대로) 리다이렉션 쓰기 동작이 일반 사용자 권한으로 수행되어, 파일 권한에 따라 실패할 수 있습니다(특히 `/dev/hello0` 권한 설정에 따라).

쓰기 이후에는 write 콜백이 한 번 실행된 것을 확인할 수 있습니다. 읽어오려면 다음을 실행합니다.

~~~
sudo cat /dev/hello0
~~~

여기서 read 콜백이 두 번 호출되는 것을 볼 수 있습니다. `cat`은 EOF(파일 끝)에 도달해야 종료되는데, 이는 read가 0을 반환할 때입니다. 첫 번째 read에서는 `off`가 0이어서 64바이트를 읽고, 두 번째 read에서는 `off`가 `text` 크기인 64가 되어 read가 0을 반환합니다.

`test.c` 애플리케이션은 한 번에 1바이트씩만 읽습니다. 만약 `testapp`을 다음처럼 실행하면

~~~
sudo ./testapp
~~~

커널 로그에서 read 함수가 65번 호출되고, `off`가 매 read마다 1씩 증가하는 것을 확인할 수 있습니다.
